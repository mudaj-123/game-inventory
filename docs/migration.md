# 云 PostgreSQL 迁移到店铺本地

迁移保留完整数据库，禁止用 CSV 重建流水。先在预演窗口用生产 dump 的受控副本完成恢复演练。
正式切换步骤：

1. 记录旧应用版本、Alembic revision、数据库版本和关键表行数；确认本地磁盘、备份和回滚容量。
2. 公告维护窗口，冻结旧系统所有写入（停止应用而不是只通知店员），验证没有活动写连接。
3. 用匹配/更新版本的官方 `pg_dump --format=custom` 导出旧 PostgreSQL；保存 SHA-256、大小、UTC
   时间和工具版本，执行 `pg_restore --list`。旧库与 dump 均保持只读可回退。
4. 在 Windows 本机创建空目标库并用 `restore.ps1` 恢复；运行 `alembic upgrade head`。不要直接
   覆盖已经在使用的本地库，也不要开放本机 5432 给 LAN。
5. 对比迁移前后 `users`、`products`、`catalog_entries`、库存、`inventory_transactions` 和预警
   表行数；SQL 检查条码唯一、库存非负、事务关联完整。抽样比对条码快照、平台、前后库存和
   用户角色，再验证管理员/STAFF 权限、幂等扫描、撤销与健康端点。
6. 将店铺客户端切换到本地 HTTPS URL，保持旧应用停止但可回退，进行现场 Android/iPhone/HID
   验收。观察日志和库存后再结束维护窗口。

若任何校验失败，不让客户端写入本地库：停止新应用、保存失败库和日志用于分析，将客户端 DNS/
书签恢复旧 URL，重新启动旧应用写入，并记录回滚时刻。只有重新冻结、制作包含回滚后新增数据的
新 dump，才能再次迁移；不能把两边的流水人工拼接。
